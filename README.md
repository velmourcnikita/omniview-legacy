# OmniView Legacy

Отдельная версия OmniView для Windows 7 SP1, Windows 8/8.1, Linux и macOS. Подразделение OmniCONTROL.

[Основная программа](https://github.com/velmourcnikita/OmniView) · [Сайт](https://velmourcnikita.github.io/OmniView/legacy) · [Сборки](https://github.com/velmourcnikita/omniview-legacy/releases)

Windows использует обычные системные окна; Linux и macOS — отдельный интерфейс без WebView. Учитель и ученик подключаются по тому же защищённому коду OV3, что и в основной программе. Пароль передаётся отдельно.

## Возможности

- Режимы учителя и ученика; класс в локальной сети с TLS и шифрованием приглашения.
- Сообщения, запросы помощи, показ основного экрана ученика с его согласия и показ экрана учителя.
- Вопросы с вариантами ответа, таймер, один ответ, результаты и HTML-отчёт.
- Проверка точных имён процессов из списка учителя после согласия ученика.
- Запрос удалённой помощи и отдельное местное согласие на пять минут. Esc, остановка показа и выход отзывают управление.
- Нативные сообщения в окне программы, экономный режим и portable-настройки.
- Проверка релизов и последних коммитов отдельного репозитория; обычный и тестовый каналы.

Интерфейс упрощён: небольшой предварительный просмотр экрана и базовый ввод щелчками/клавиатурой. Для сложных действий и большого экрана рекомендуется основная версия на Windows 10/11. Полноэкранного просмотра, перетаскивания и банка вопросов в интерфейсе Legacy пока нет. Нажатия на экран отправляются только после согласия ученика. Выбранному ученику можно отправить сообщение; без выбора оно уходит всему классу.

## Запуск

В релизе скачай оба EXE одной архитектуры. Убери префиксы `win32-` или `win64-`, сохрани имена `OmniView.exe` и `OmniView-Student.exe` в одной папке. Первый запускает учителя, второй — ученика. Других DLL для локальной статической сборки не нужно.

На Windows 7 нужна SP1. Windows XP/Vista не поддерживаются. Сборки рассчитаны на Windows 7, но до испытания на физической системе совместимость считается экспериментальной. Тесты на современной Windows и проверка импортов не заменяют такой запуск.

Ошибка `ProcessPrng` у основной программы означает неподходящую для старой системы сборку. В Legacy стандартная библиотека пересобрана для `win7`, генератор случайных чисел использует `RtlGenRandom`. Подменять `bcryptprimitives.dll` не нужно.

## Portable и обновления

Создай пустой `portable.flag` рядом с EXE: настройки и отчёты попадут в соседнюю `data`. Без него используется `%LOCALAPPDATA%/OmniView-Legacy`. Для обновления нужна доступная для записи папка программы.

В Windows при старте проверяются релизы. Кнопка «Проверить обновления» показывает последний коммит. Флажок «Новые коммиты» выбирает тестовые сборки, опубликованные только после успешных проверок. Загрузка проверяет SHA-256 по метаданным GitHub. Установка запускается по нажатию после завершения сеанса, сохраняет прежние файлы и перезапускает приложение. Старые Windows могут не подключаться к GitHub из-за системных настроек TLS или сертификатов; файлы тогда можно скачать на другом ПК и перенести вручную. Класс не требует интернета.

## Сборка

Нужны Rust 1.99.1 с `rust-src`, MSVC Build Tools для x86/x64, Windows SDK и LLVM-MinGW для компилятора ресурсов `windres`.

```powershell
rustup component add rust-src rustfmt
$env:RUSTC_BOOTSTRAP='1'
cargo build '-Zbuild-std=std,panic_abort' --release --locked --target i686-win7-windows-msvc
cargo build '-Zbuild-std=std,panic_abort' --release --locked --target x86_64-win7-windows-msvc
./scripts/package.ps1 -Architecture x86 -SkipBuild
./scripts/package.ps1 -Architecture x64 -SkipBuild
```

`build-std` здесь используется с закреплённым компилятором для платформы Tier 3, готовые библиотеки которой Rust не распространяет. Это не сборка под современную платформу с изменённой подписью ОС. Конфигурация включает статическую CRT; отдельные Visual C++ DLL не нужны.

## Проверки

```powershell
$env:RUSTC_BOOTSTRAP='1'
cargo test '-Zbuild-std=std,panic_abort' --locked --target i686-win7-windows-msvc
./dist/x86/OmniView.exe --self-test
python scripts/check-imports.py ./dist/x86/OmniView.exe
```

Сетевое ядро перенесено из OmniView 0.6.0. В этом репозитории оно развивается отдельно; обновления протокола должны сопровождаться проверкой совместимости. Материалы конкурса, презентации и полные проектные ZIP сюда не входят.

Основание: [Rust Windows 7 targets](https://doc.rust-lang.org/rustc/platform-support/win7-windows-msvc.html), [ограничения WebView2](https://blogs.windows.com/msedgedev/2022/12/09/microsoft-edge-and-webview2-ending-support-for-windows-7-and-windows-8-8-1/).

## Linux и macOS

| Платформа | Файлы релиза | Что доступно |
| --- | --- | --- |
| Windows 7 SP1/8/8.1 x86/x64 | win32/win64 EXE | Все перечисленные функции, базовое управление с согласием |
| Linux x64, X11, glibc 2.35+ | linux-x64-OmniView и linux-x64-OmniView-Student | Класс, сообщения, помощь, задания, отчёты, проверка процессов, показ экрана |
| Linux x64, Wayland | те же файлы | Класс и задания; показ экрана пока недоступен |
| macOS 11+ Intel / Apple Silicon | macos-x64 / macos-arm64 DMG | Класс, сообщения, помощь, задания, отчёты, проверка процессов, показ экрана после системного разрешения |

Приём удалённого управления в Linux/macOS пока не реализован. Кнопки не выдают несуществующее согласие: серверный запрос не разрешает ввод на этих системах. BSD, Android, iOS, Linux ARM, 32-битный Linux и дистрибутивы с musl пока не входят в сборки. Поддержка Linux не означает проверку каждого дистрибутива. Первые Unix-сборки экспериментальные.

Linux и macOS Intel проходят выполнение модульных тестов на своих системах. Версия Apple Silicon собирается на Intel Mac для ARM64; её тесты компилируются, но запуск на настоящем Apple Silicon пока не проверен.

### Linux

После скачивания убери префикс `linux-x64-`, положи оба файла в одну папку и разреши запуск:

```sh
chmod +x OmniView OmniView-Student
./OmniView
# на ученике:
./OmniView-Student
```

Нужна настольная сессия и OpenGL. На Debian/Ubuntu библиотеки выполнения: `libx11-6 libxrandr2 libxi6 libxcursor1 libxinerama1 libxcb1 libxcb-randr0 libdbus-1-3 libxkbcommon0 libxkbcommon-x11-0 libgl1 libwayland-client0`. Ubuntu 22.04+ и Debian 12+ подходят по заявленной базе glibc; конкретную машину нужно проверить. Fedora/openSUSE/Arch могут использовать сборку при наличии совместимых библиотек. Alpine/musl требуют отдельной сборки, которой пока нет.

В Wayland интерфейс и сеть работают, но эта версия не запрашивает портал записи экрана. Для показа экрана выбери X11 при входе. Код не обходит разрешения Wayland.

### macOS

Открой DMG своей архитектуры и скопируй приложения учителя и ученика в доступную папку. Сборка не подписана сертификатом Apple Developer и не нотарифицирована. Разрешай запуск только скачанного из этого репозитория файла через системный интерфейс macOS; системную защиту целиком отключать не нужно.

При включении показа программа запрашивает системное разрешение «Запись экрана». Если доступ закрыт, разреши его для OmniView Legacy в настройках конфиденциальности macOS и перезапусти программу. Без доступа передача не включается; проверка сборки на Mac не подтверждает работу записи экрана на пользовательском Mac.

### Сборка Unix

```sh
# Debian/Ubuntu, зависимости сборки:
sudo apt-get install pkg-config libx11-dev libxrandr-dev libxcb1-dev libxcb-randr0-dev libdbus-1-dev libxkbcommon-dev libxkbcommon-x11-0 libgl1-mesa-dev libwayland-dev
cargo build --release --locked
```

На macOS нужны Command Line Tools и Rust. GitHub Actions собирает Intel и Apple Silicon на соответствующих Mac. Наличие сборки не заменяет проверку системных разрешений на целевом устройстве.

Linux/macOS проверяют релиз и последний коммит, а заменяются вручную после завершения урока. Windows имеет встроенный загрузчик и установку по нажатию. Unix-настройки: Linux — `$XDG_DATA_HOME/omniview-legacy` или `~/.local/share/omniview-legacy`, macOS — `~/Library/Application Support/OmniView-Legacy`. `portable.flag` переключает на соседнюю `data`, если папка доступна для записи.
